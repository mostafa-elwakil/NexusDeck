# NexusDeck Companion Server on Linux

Run the NexusDeck companion server (and its web Studio UI) on a Linux box —
Ubuntu/Debian, Fedora/RHEL, or Arch — instead of (or alongside) the Windows
`NexusDeckCompanion.exe`. The ESP32 CYD device firmware works **unchanged**.

Everything is per-user: a Python venv, the server's state, a systemd **user**
service, and the self-signed TLS cert. No system packages are installed
beyond python3/pip.

## Files this installs

| What                                        | Where                                          |
|---------------------------------------------|------------------------------------------------|
| Python venv                                 | `~/.local/share/nexusdeck/venv`                |
| Server state (profiles, settings, cert, logs)| `~/.local/share/nexusdeck/state` (`NEXUSDECK_DATA_DIR`) |
| Self-signed cert + key                      | `~/.local/share/nexusdeck/state/nexusdeck.crt` / `nexusdeck.key` |
| systemd user unit                           | `~/.config/systemd/user/nexusdeck.service`     |
| `/etc/hosts` entry (marker `# nexusdeck`)   | `127.0.0.1 nexusdeck`                          |
| Trusted cert (system store)                 | `/usr/local/share/ca-certificates/nexusdeck.crt` (Debian) or the `*-anchors/` dir on Fedora/Arch |
| Chromium NSS db trust                       | `~/.pki/nssdb` (only if `certutil` is installed) |

The cert is **generated by the server itself** (`cryptography`) — the
installer just pre-creates it via `python server.py --ensure-cert`. It covers
`nexusdeck`, `localhost`, `127.0.0.1` and the machine's LAN IPs, and is valid
for 10 years. There is no manual openssl step and no cert-path environment
variable in the code.

## Requirements

- Linux with systemd (for the background service) and python3 >= 3.10
- A cloned NexusDeck repo checkout **kept in place** — the service runs
  `python server.py` directly from `streamdeck-simulator/server/` in the
  repo (matching the server's own dev-launch logic), so don't move or delete
  the clone. Re-run the installer after moving it.
- Root only for: `/etc/hosts`, cert trust, lingering (the script uses `sudo`).

## Install

```bash
git clone https://github.com/mostafa-elwakil/NexusDeck.git
cd NexusDeck
tools/linux/install-server.sh                 # from the repo root
# or: tools/linux/install-server.sh --repo /path/to/NexusDeck --https-port 8443
```

The installer is idempotent — re-run it any time (update = `git pull`, then
re-run; pip and the cert are reused).

HTTPS is on by default (`NEXUSDECK_HTTPS=0` disables it — see `server.py`).
Because a user-level service cannot bind port 443, the installer sets
`NEXUSDECK_HTTPS_PORT=8443`, so the primary URL is:

- **Studio UI:** `https://nexusdeck:8443/`
- **Plain HTTP (ESP32 uses this):** `http://<server-ip>:8765/`

Want plain `https://nexusdeck/` (port 443)? Allow unprivileged binds, then
set the unit's `NEXUSDECK_HTTPS_PORT=443` (or re-run the installer with
`--https-port 443`):

```bash
echo 'net.ipv4.ip_unprivileged_port_start=0' | sudo tee /etc/sysctl.d/99-nexusdeck.conf
sudo sysctl --system
```

The server also auto-falls back 443 → 8443 on its own if the port is taken.

## Run / stop / logs

```bash
systemctl --user status nexusdeck
systemctl --user start|stop|restart nexusdeck
journalctl --user -u nexusdeck -f        # follow the log
```

Lingering is enabled at install, so the server starts at **boot without
login**. To revert: `sudo loginctl disable-linger $USER`.

Run it manually instead of the service:

```bash
cd streamdeck-simulator/server
NEXUSDECK_DATA_DIR=~/.local/share/nexusdeck/state ~/.local/share/nexusdeck/venv/bin/python server.py
```

## Pair the ESP32

1. Flash the ESP32 firmware as usual — **no changes needed**.
2. In the device's WiFi setup portal, point `SERVER_URL` at the Linux
   machine's IP: `http://<linux-ip>:8765/`.
3. Open the Studio UI and complete ESP32 pairing in the web UI (the device
   on the LAN needs the pairing token; loopback requests are always allowed).

## Firewall

Allow the HTTP port the device talks to, and the HTTPS port browsers use:

```bash
sudo ufw allow 8765/tcp      # Ubuntu: ESP32 HTTP
sudo ufw allow 8443/tcp      # Studio UI (skip if you use 443)
# firewalld:
sudo firewall-cmd --add-port=8765/tcp --add-port=8443/tcp --permanent && sudo firewall-cmd --reload
```

## Update

```bash
cd NexusDeck && git pull
tools/linux/install-server.sh
systemctl --user restart nexusdeck   # installer already restarts via enable --now
```

## Uninstall

```bash
tools/linux/uninstall-server.sh          # asks before deleting data
tools/linux/uninstall-server.sh --yes    # remove everything, no prompts
```

Removes the services (including `nexusdeck-companion.service`, see below),
and after confirmation the venv + state, the `/etc/hosts` line, and the cert
trust (system store + Chromium NSS db). Keeps the repo checkout and boot
lingering.

## Troubleshooting

**"Another NexusDeck server is already running on port 8765"**
Exactly one server can run at a time (single-instance lock in `server.py`).
Stop the service before running a manual copy: `systemctl --user stop nexusdeck`.
If you toggled **"Run in background" inside Studio**, that created a second
unit (`nexusdeck-companion.service`); the installer replaces it with
`nexusdeck.service` — use one or the other, not both.

**`https://nexusdeck:8443/` shows a cert warning in Chrome/Chromium**
System trust alone isn't enough for Chromium on Linux; it reads its NSS db.
The installer handles this if `certutil` exists (Debian: `sudo apt-get
install libnss3-tools`, Fedora: `sudo dnf install nss-tools`, Arch:
`sudo pacman -S nss`). Re-run the installer afterwards, or accept the
warning once (Advanced > Proceed).

**Firefox warning**
Firefox uses per-profile stores: Settings > Privacy & Security >
Certificates > View Certificates > Authorities > Import
`~/.local/share/nexusdeck/state/nexusdeck.crt`.

**`nexusdeck` doesn't resolve**
The `/etc/hosts` entry is missing (no sudo at install?). Add it:
`echo '127.0.0.1 nexusdeck' | sudo tee -a /etc/hosts`.

**Port 443 "unavailable" in the log**
Expected for user services — the server falls back to 8443. See the sysctl
snippet above to really use 443.

**Service doesn't start / "Failed to connect to bus"**
The systemd user session doesn't exist yet (fresh SSH/first boot). Log out
and back in, or reboot, then `systemctl --user start nexusdeck`. Check
`journalctl --user -u nexusdeck -f` for details.

**pip build errors for Pillow / cryptography**
Modern distros get prebuilt wheels (x86_64 and aarch64). On very old distros
install a compiler and headers first (Debian: `build-essential libffi-dev`;
Fedora: `gcc libffi-devel`) and re-run.

**Copy-to-clipboard buttons do nothing**
The server shells out to `xclip` for clipboard on Linux — install it
(`xclip` on all three families) if you use that feature.

## What works differently vs. Windows

The firmware and web Studio are the same; the ESP32 setup portal just points
`SERVER_URL` at the Linux server's IP. Differences inside the server:

- **Works unchanged:** pairing token, profiles, pages rendering, resource
  monitoring (psutil), HTTP+HTTPS servers, OBS WebSocket actions
  (`obsws-python`; optional `OBS_WS_HOST` / `OBS_WS_PORT` / `OBS_WS_PASSWORD`).
- **Windows-only, so absent on Linux:** the installed-apps list (read from
  the Windows Uninstall registry — returns empty), PowerShell-based system
  actions, the Startup-folder autostart shortcut (Linux uses the systemd
  unit instead — the Studio toggle supports this), and the console
  minimize/pop-up niceties (no-ops).
- **Autostart:** on Windows it's a Startup `.lnk`; here it's the systemd user
  service installed by this script (plus lingering for boot start).
